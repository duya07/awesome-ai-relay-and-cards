# 14 维发卡网与 API 中转站实战避坑手册

本项目在长期维护与自动化评测中，总结提炼出针对第三方 AI 发卡网与 API 中转站的 14 项核心暗坑。在执行终端验真与向用户推荐渠道时，必须严格逐条排查。

---

## 一、发卡网实战避坑排查（8 大维度）

### 1. 防“起步价刺客”（SKU 联动套路）
- **套路特征**：商品列表卡片标价 `¥5.00 起`，诱导用户点击。点进详情页后，下拉框默认选中的只是“体验邀请码”或“共享1小时”，真正需要的“独享成品号”实际标价跳涨至 `¥25+` 甚至更高。
- **排查要求**：严禁抓取外部最低起步价。脚本必须模拟选中用户需要的确切规格（如 `成品号`、`独享带邮箱`），提取联动后的真实结算金额。

### 2. 起充门槛与资金沉淀陷阱
- **套路特征**：商品标价 8 元，但在收银台充值时提示“本站最低充值 20 元起”，导致剩余资金被强制沉淀在小卡网内，面临跑路损失。
- **排查要求**：检查店铺是否支持单笔直接付款，若存在起充门槛，必须在推荐中显式标注：`[起充门槛: ￥XX]`。

### 3. 幽灵库存与虚假秒发
- **套路特征**：店铺页面标有“库存: 999”，但点击“立即购买”后弹窗提示“该商品补货中，付款后排队 24 小时内人工发货”，实际属于无现货的空手套白狼。
- **排查要求**：核查购买按钮的实时状态是否为真在售（如 `in_stock: true` 且按钮文本为 `立即购买`），自动剔除标注“预售”、“补货中”或库存为 0 的店铺。

### 4. 交付邮箱质量分级（账号安全核心）
- **套路特征**：同样标榜“带邮箱交付”，但实际使用随时会失效的临时邮箱，导致账号无法长期使用。
- **分类标准**：
  - **T0 级（安全推荐）**：一手 Gmail / Outlook / ProtonMail，附带辅助验证邮箱与安全码；
  - **高危级（极易封号/找回）**：自建域名企业邮（形如 `@xxx-mail.com`），域名注销或商家停服后无法接收验证码；
  - **不可用级**：不提供邮箱，仅提供一段临时 `Session Token` 或 `Cookie`。

### 5. 商家严苛免责条款（售后陷阱）
- **套路特征**：购买须知中暗藏霸王条款，例如：“收到账号 30 分钟内必须首登，超时不售后”、“必须使用指定美国住宅 IP 登录，机房 IP 触发风控概不退换”。
- **排查要求**：提取商品详情中的 `notes` 或 `购买须知`，高亮提取质保时长（如：`首登质保`、`质保24小时`）及网络环境要求。

### 6. 隐藏跑马灯优惠码（折上折）
- **套路特征**：部分发卡小铺在顶部横幅（Banner）或公告跑马灯中提供了满减码（如“输入 `vip888` 立减 3 元”），普通用户容易遗漏。
- **排查要求**：扫描店铺 Announcement 或 Notice 字段，抓取可用券码并计算折后实付价。

### 7. 易支付隐蔽渠道加价手续费
- **套路特征**：标价 ¥20，跳转到第三方免签/聚合易支付网关时，强制加收 `3% ~ 15%` 的手续费，实付金额明显高于标价。
- **排查要求**：核查结算收银台是否包含渠道加价费率。

### 8. 黑卡退款跑路风险（一周封号）
- **套路特征**：卖家使用盗刷信用卡（CVV）或透支虚拟卡代开会员，官方会在 7~14 天内发起拒付（Chargeback），导致账号被彻底停用且卖家已失联。
- **排查要求**：对远低于官方成本价的“代充/长期号”保持警惕，建议用户小额按需购买，避免长期年费充值。

## 二、API 中转站避坑排查（6 大维度）

### 9. 假官转与模型掺水降级
- **套路特征**：用户请求昂贵的 `Claude 3.7 Sonnet` 或 `GPT-4o`，中转站在后台悄悄降级转发到廉价的 `Haiku`、逆向模型甚至 `DeepSeek`，但扣费依然按高价模型扣除。
- **排查要求**：通过 MODELOC、Veridrop 或禾维鉴别器抽检模型纯度，核对输出流式特征与 System Prompt 响应。

### 10. 倍率双重膨胀刺客
- **套路特征**：中转站宣传“1元购买 1 刀额度”，但在计费后台设置了“用户分组倍率 1.5”以及“模型专属倍率 2.0”，实际扣费倍率高达 `1.5 × 2.0 = 3.0` 倍，实际比官方贵得多。
- **排查要求**：统一换算为**每百万 Token 实际人民币花费**（`折算单价 = 官方牌价 × 分组倍率 × 模型倍率`），坚决不信单一的充值比率宣传。

### 11. 上下文长度静默截断
- **套路特征**：宣称支持 128K / 200K 长上下文，实际当输入超过 8K 或 16K 时，网关在未报错的情况下静默截断前端 Prompt，导致代码补全或长文档总结质量断崖式下跌。
- **排查要求**：排查中转站是否通过长文本探针测试，关注实际上下文可用上限。

### 12. 逆向 Web 接口冒充商业 API
- **套路特征**：使用爬虫或逆向 Web 网页端模拟 API，此类接口不仅不稳定、经常出现验证码 429 报错，而且输出格式不完整、容易缺失 Tool Use（函数调用）功能。
- **排查要求**：通过接口返回的 Header、首字延迟（TTFT）与可用率探针排查逆向成分。

### 13. 超高充值返利与庞氏跑路周期
- **套路特征**：站点上线数周后突然推出“充 100 送 300”、“年卡终身畅享”等超常规返利活动，通常是站长资金链断裂准备卷款跑路的危险信号。
- **排查要求**：遇到返利超过 50% 的中转站，直接触发资金安全高危预警，严禁推荐大额充值。

### 14. 域名突然失效与跨域换绑
- **套路特征**：由于不可抗力或封禁，中转域名频繁迁移，客户端配置直接报错失效。
- **排查要求**：通过 `check_links.py` 自动化跟踪 301/302 重定向目标，提示换绑网址。
